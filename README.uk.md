# DTEK Telegram Bot для Home Assistant

[English](README.md) · **Українська**

[![Додати репозиторій застосунку до Home Assistant](https://my.home-assistant.io/badges/supervisor_add_addon_repository.svg)](https://my.home-assistant.io/redirect/supervisor_add_addon_repository/?repository_url=https%3A%2F%2Fgithub.com%2Fgroove-max%2Fha-dtek-telegram-bot)
[![Ліцензія PolyForm Noncommercial](https://img.shields.io/badge/License-PolyForm_Noncommercial-blue.svg)](LICENSE)

**Графіки відключень світла ДТЕК і сповіщення про електроенергію в Telegram** із Home Assistant. Повідомляйте себе в особистому чаті, мешканців будинку, сусідів або підписників каналу про зміни графіка й наближення відключення та підтримуйте одне актуальне закріплене повідомлення.

Застосунок отримує дані ДТЕК для адреси через [DTEK Monitor](https://github.com/groove-max/ha-dtek-monitor/blob/main/README.uk.md). Додаткові локальні датчики напруги можуть підтверджувати фактичне зникнення та повернення світла. Через інтеграцію підтримуються оператори **Одеської, Київської, Дніпропетровської областей та міста Києва**.

[Встановлення](#installation) · [Перше налаштування](#setup) · [Визначення живлення](#power-detection) · [Розв’язання проблем](#troubleshooting) · [Повний посібник](DOCS.uk.md)

<a id="features"></a>
## Можливості

- Сповіщення про зміну графіка відключень і груп адреси.
- Попередження перед плановим відключенням за обрану кількість хвилин.
- Відключення через опівніч без повторних попереджень; непідтверджене завершення позначається як невідоме, якщо інтеграція передає межі перевіреної публікації.
- Причини відключення та орієнтовний час відновлення за даними ДТЕК.
- Визначення зникнення й повернення світла за придатними локальними датчиками, із затримками для відсіювання коротких провалів.
- Одна фаза або кілька датчиків напруги, зокрема для часткових відключень.
- Окремі сповіщення про низьку, високу та відновлену нормальну напругу.
- Оновлення закріпленого статусу без постійного створення нових повідомлень.
- Вебредактор адрес, сповіщень і шаблонів із попереднім переглядом та діагностикою.

Приклад закріпленого повідомлення — умовні адреса, показання та графік:

```text
🟢 Одеса • Приклад будинку
🔵 Група GPV3.1
✅ Електропостачання: норма
🔌 🟢 L1: 230.0 В
📅 Найближче планове:
17.10 — 19:00–22:00
🕒 Оновлено: 17.10.2026 18:00
```

Вебредактор і стандартні повідомлення наразі українською. Формулювання та мову повідомлень можна змінити через [шаблони](DOCS.uk.md#templates).

<a id="requirements"></a>
## Який проєкт встановлювати?

| Проєкт | Призначення | Спосіб встановлення |
| --- | --- | --- |
| [DTEK Monitor](https://github.com/groove-max/ha-dtek-monitor/blob/main/README.uk.md) | Отримує дані ДТЕК, створює сенсори й календарі HA | Користувацька інтеграція HACS або ручне копіювання |
| **DTEK Telegram Bot** — цей репозиторій | Надсилає повідомлення за цими даними та показаннями локальних датчиків | Репозиторій застосунків HA, не HACS |

Потрібні **Home Assistant OS**, Home Assistant **2026.3.0+** та пристрій `amd64` або `aarch64`. Також потрібні налаштована адреса будинку в DTEK Monitor, токен Telegram-бота й ID чату.

**Бот 0.4.0 працює з DTEK Monitor 1.7.0 та необов’язковою бета-версією 2.0.0b1.** Проєкти мають незалежну нумерацію версій. Перехід інтеграції на 2.0 не потребує нової версії бота. [Сумісність і перехід на beta →](DOCS.uk.md#dtek-monitor)

У Monitor 2.0 можна додати адресу безпосередньо або використати будинок, прив’язаний до одеського особового рахунку. Бот використовує публічні сутності цього будинку. Вхід до кабінету, номери рахунків, показання лічильників і нагадування про їх передавання належать до інтеграції; цей бот їх не надсилає й не обробляє. Особистий чат Telegram також отримує сповіщення про будинок.

**Кілька адрес, чатів або ботів? Достатньо одного встановлення.** Кожна адреса має власні сповіщення, датчики, вибір групи та профіль Telegram-бота. Залиште основного бота або додайте інший токен один раз на вкладці **Telegram-боти** та використовуйте профіль для кількох адрес. Дивіться [адреси, чати й боти](DOCS.uk.md#destinations).

У нових версіях Home Assistant додатки **add-ons** називаються **apps**. У старіших версіях меню має назву **Add-ons / Додатки**. HA Container не містить менеджера застосунків. Дивіться [вимоги Home Assistant](https://www.home-assistant.io/apps).

<a id="installation"></a>
## Встановлення

1. Встановіть [DTEK Monitor](https://github.com/groove-max/ha-dtek-monitor/blob/main/README.uk.md#installation), додайте адресу та перевірте її сутності.
2. Створіть окремого бота через [@BotFather](https://t.me/BotFather), команда `/newbot`.
3. Оберіть призначення: **особисто вам** — відкрийте бота й натисніть **Розпочати**; **група** — додайте бота й дозвольте повідомлення; **канал** — додайте адміністратором із правами публікації/редагування. Для закріплення в групі чи каналі потрібні відповідні права.
4. Знайдіть ID чату за [інструкцією Telegram](DOCS.uk.md#telegram). ID групи чи каналу зазвичай від’ємний — збережіть знак мінус.
5. Відкрийте **Налаштування → Застосунки → Встановити застосунок → ⋮ → Репозиторії**. У старіших версіях: **Налаштування → Додатки → Магазин додатків → ⋮ → Репозиторії**.
6. Додайте `https://github.com/groove-max/ha-dtek-telegram-bot` і встановіть **DTEK Telegram Bot**. Кнопка вище відкриває діалог додавання репозиторію.
7. На вкладці **Конфігурація** застосунку введіть `telegram_bot_token` і `telegram_chat_id`. Запустіть застосунок і натисніть **Відкрити вебінтерфейс**.

Зазвичай створювати токен доступу Home Assistant не потрібно: застосунок автоматично використовує доступ Supervisor.

<a id="setup"></a>
## Налаштування першої адреси

Для особистого використання достатньо розмови з ботом — створювати групу чи канал не потрібно. Для спільної розсилки спочатку перевірте налаштування в особистому чаті або тестовій групі.

1. На вкладці **Налаштування** вебредактора додайте адресу зі знайдених пристроїв. Нова інсталяція починає з порожнього списку адрес. Виявлення автоматично підбирає префікс сутностей HA — не вгадуйте його за назвою вулиці.
2. Задайте зрозумілу назву. Залиште окремий ID чату адреси порожнім, щоб використовувати основний чат застосунку.
3. Залиште **обрану групу** порожньою, щоб відстежувати всі групи будинку, особливо у спільному чаті мешканців. Для особистих сповіщень за потреби виберіть підтверджену групу квартири. Цей параметр незалежний від особистої групи в Monitor 2.0.
4. Увімкніть потрібні сповіщення. Без локальних датчиків почніть зі змін графіка/груп і закріпленого статусу.
5. Для локального визначення живлення оберіть режим із таблиці нижче та сутності напруги.
6. Перевірте конфігурацію й натисніть **Зберегти й перезапустити**. Саме збереження не застосовує параметри до вже запущених модулів.
7. Перевірте діагностику. Перегляньте шаблон і надішліть тестове повідомлення, щоб перевірити чат та права бота. Це справжнє повідомлення з тестовою позначкою.

**Ознаки успішного налаштування:** HA підключений, адресу й групу знайдено, тест з’явився в потрібному чаті, статусне повідомлення редагується. Без свіжих вимірювань локальний стан живлення цілком коректно може бути `unknown`.

Для примусового тестового спрямування в особистий чат, групу або канал перед запуском задайте `test_chat_id` у параметрах застосунку. Він замінює всі адресати, включно з окремими чатами адрес і тестами шаблонів. Докладніше: [ізольоване тестування](DOCS.uk.md#testing).

<a id="power-detection"></a>
## Як визначати наявність світла

| Обладнання | Режим | Що можна визначити |
| --- | --- | --- |
| Немає локального датчика | `dtek_only` | Стан за даними ДТЕК, який може відставати від реальності. |
| Один датчик вхідної напруги з резервним живленням | `voltage_only` | Зникнення світла за свіжою низькою/нульовою напругою та відновлення за свіжою додатною напругою. |
| Один датчик, який вимикається разом із мережею | `voltage_only` | Свіжу напругу, поки він працює; його зникнення означає `unknown`, а не підтверджене відключення. |
| Резервований датчик втрати мережі + лічильник напруги, наприклад ATORCH | `loss_plus_voltage` | Незалежне підтвердження, коли лічильник напруги стає недоступним або перестає оновлюватися. |

**Одного датчика достатньо**, якщо він продовжує вимірювати й передавати **напругу на вході мережі**, зокрема нуль, під час відключення. Його шлюз, мережеве обладнання та HA також мають залишатися онлайн. Резервований вихід інвертора не показує наявності зовнішньої мережі.

У парі датчиків на одній лінії свіже явне показання «мережі немає» від інвертора разом із недоступним або завмерлим ATORCH підтверджує відключення після заданих затримок. Події можуть надійти в будь-якому порядку. Якщо зникає лише ATORCH, а інвертор показує наявність мережі, результат — невідомий локальний стан, а не хибне відключення.

У цьому парному режимі низька/нульова напруга також потребує свіжого підтвердження від незалежного датчика втрати мережі. Якщо інвертор показує наявність мережі або його показання недостовірне, нульова напруга дає `unknown`. Повернення нормальної напруги після цього не створює хибного повідомлення «Світло з’явилось».

До затримки сповіщення додається інтервал передавання даних. Датчик, який звітує раз на хвилину, не гарантує повідомлення за кілька секунд після фізичної події. Добирайте термін актуальності й затримки за реальними вимірюваннями. [Приклади, затримки та правила переходів →](DOCS.uk.md#power)

Окремі сповіщення про втрату й повернення даних **типово вимкнені** (`power.telemetry_notifications: false`). Закріплений статус продовжує відображати відсутність вимірювань. Повідомлення про підтверджене відключення та відновлення залишаються доступними.

<a id="schedules"></a>
## Графіки, групи та статус

- Графік — це план, а не вимірювання. Аварійні обмеження ДТЕК можуть його змінювати.
- Кілька груп адреси відображаються окремо. Вибір групи не підтверджує, що саме до неї належить квартира.
- Для операторів із прихованими номерами показуються **«Варіант 1», «Варіант 2»**. Це локальні позначення, а не офіційні номери черг.
- Невдалі або неузгоджені перевірки призупиняють сповіщення про графік. Збережені календарі лише для перегляду не запускають сповіщень.
- Неопубліковану дату бот не оголошує днем без відключень.
- Типовий режим статусу редагує одне повідомлення. `send_new` доступний, якщо вам потрібні нові дописи.

<a id="troubleshooting"></a>
## Розв’язання проблем

| Симптом | Що зробити |
| --- | --- |
| Не знаходжу застосунок | Додайте репозиторій до магазину застосунків HA, не HACS. Перевірте спосіб встановлення HA та архітектуру процесора. |
| Немає адреси серед знайдених | Перевірте сутності будинку й з’єднання з HA. У Monitor 2.0 перевірте прив’язку будинку до рахунку; сам рахунок не є адресою для бота. [Інструкція підключення](DOCS.uk.md#dtek-monitor). |
| Monitor 1.7.0 показує «Current schedule coverage is missing» під час налаштування | Відома проблема інтеграції може блокувати створення сутностей. У Monitor 2.0.0b1 її виправлено; дивіться [перехід на beta та відкат](DOCS.uk.md#monitor-upgrade). |
| Немає повідомлень Telegram | Перевірте токен, повний ID чату й права бота; надішліть тест шаблону та перегляньте журнал застосунку. |
| Налаштування збережено, але поведінка стара | Скористайтеся **Зберегти й перезапустити** та перевірте індикатор незастосованих змін. |
| Стан живлення `unknown` | Перевірте доступність датчика, час звітування та максимальний вік даних. Старе число не підтверджує наявності світла. |
| Статус постійно надходить новими дописами | Перевірте `delivery_mode`: потрібен `pinned_edit` і можливість редагувати власне повідомлення. |
| Група повторюється у власному шаблоні | Скиньте цей шаблон до актуального стандартного або виправте перевизначення. Власні шаблони зберігаються після оновлення. |
| Сповіщення про графік зупинилися | Перевірте з’єднання DTEK Monitor та, у версії 2.0, **Доступність графіка**. Відсутня публікація не означає підтверджений порожній графік. [Стани доступності](DOCS.uk.md#schedule-availability). Контроль за локальними датчиками може продовжуватися. |
