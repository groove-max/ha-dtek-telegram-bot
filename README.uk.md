**Сповіщення про відключення ДТЕК, актуальний стан живлення й особисті покази — у Telegram.** Повідомляйте групу чи канал будинку або користуйтеся власним кабінетом у приватній розмові. Один застосунок Home Assistant підтримує обидва режими, кілька адрес і токенів ботів.

Працює з [DTEK Monitor](https://groove-max.github.io/ha-dtek-monitor/uk/) для **Одеської області, міста Києва, Київської та Дніпропетровської областей**. Локальні датчики живлення необов’язкові. Кабінети Київської та Дніпропетровської областей підтримуються експериментально.

**[Встановити](#installation)** · [Документація](https://groove-max.github.io/ha-dtek-telegram-bot/uk/) · [Останній випуск](https://github.com/groove-max/ha-dtek-telegram-bot/releases/latest) · [Інтеграція DTEK Monitor](https://github.com/groove-max/ha-dtek-monitor)

![Ілюстрація закріпленого статусу будинку й особистого меню ДТЕК із вигаданими даними](docs/images/telegram-overview.png)

## Оберіть свій сценарій

| Мені потрібно | З чого почати |
| --- | --- |
| Графіки й сповіщення для будинку, групи чи каналу | [Будинковий режим](docs/BUILDING.uk.md); вхід до кабінету ДТЕК не потрібен. |
| Лише графіки за адресою, особисто мені | Той самий [будинковий режим](docs/BUILDING.uk.md) із приватним одержувачем. |
| Група квартири з кабінету, історія й передача показів | [Особистий режим](docs/PERSONAL.uk.md); підключіть кабінет у DTEK Monitor і призначте свого приватного користувача Telegram. |
| Фактичний стан живлення та якість напруги | Додайте придатні [датчики HA](docs/POWER.uk.md) до будь-якого режиму. |

Ви створюєте власного бота через BotFather і керуєте одержувачами в Home Assistant. Повідомлення чужому боту не створює підписку на адресу й не надає доступ до рахунку. Вебредактор і стандартні повідомлення українською; інструкції доступні українською та англійською.

<a id="features"></a>
## Можливості

- Сповіщення про зміну графіка відключень і груп адреси.
- Попередження перед плановим відключенням за обрану кількість хвилин.
- Відключення через опівніч без повторних попереджень; непідтверджене завершення позначається як невідоме, якщо інтеграція передає межі перевіреної публікації.
- Причини відключення та орієнтовний час відновлення за даними ДТЕК.
- Визначення зникнення й повернення світла за придатними локальними датчиками, із затримками для відсіювання коротких провалів.
- Одна фаза або кілька датчиків напруги, зокрема для часткових відключень.
- Окремі сповіщення про низьку, високу та відновлену нормальну напругу.
- Оновлення закріпленого статусу без постійного створення нових повідомлень.
- PNG-графік усіх груп на сьогодні або завтра з особистого меню.
- Історія показів ДТЕК, необов’язкові нагадування й передача накопичувальних показів після явного підтвердження у приватному режимі.
- Підказки від сумісного датчика енергії та калібрування з «Мій ДТЕК»; для ручного введення датчик не потрібен.
- Вебредактор адрес, сповіщень і шаблонів із попереднім переглядом та діагностикою.

Приклад закріпленого повідомлення — умовні адреса, показання та графік:

```text
🟢 Одеса • Приклад будинку
🔵 Група GPV3.1
✅ Електропостачання: норма
🔌 🟢 L1: 230.0 В
📅 Найближче планове:
17.10 — 19:00–22:00
🕒 Оновлено: 17.10.2026 18:00
```

Вебредактор і стандартні повідомлення наразі українською. Формулювання та мову повідомлень можна змінити через [шаблони](DOCS.uk.md#templates).

<a id="requirements"></a>
## Який проєкт встановлювати?

| Проєкт | Призначення | Спосіб встановлення |
| --- | --- | --- |
| [DTEK Monitor](https://github.com/groove-max/ha-dtek-monitor/blob/main/README.uk.md) | Отримує дані ДТЕК, створює сенсори й календарі HA | Користувацька інтеграція HACS або ручне копіювання |
| **DTEK Telegram Bot** — цей репозиторій | Надсилає повідомлення за цими даними та показаннями локальних датчиків | Репозиторій застосунків HA, не HACS |

Потрібні **Home Assistant OS**, Home Assistant **2026.3.0+** та пристрій `amd64` або `aarch64`. Також потрібні будинок або підключений кабінет у DTEK Monitor і токен власного Telegram-бота. Після `/start` оберіть одержувача зі знайдених користувачів/чатів або введіть числовий ID вручну.

**Бот 0.5.0-rc2** зберігає будинкові сповіщення з Monitor 1.7.0 і 2.0.0b1. Для кабінету й PNG-таблиць потрібні **бот 0.5.0-rc2 або новіший** та **Monitor 2.0.0-rc2 або новіший**. Номери версій проєктів незалежні. [Сумісність і налаштування →](DOCS.uk.md#dtek-monitor)

**Два режими в одному встановленні.** «Графіки за адресою» надсилає сповіщення в особистий чат, групу чи канал без входу до кабінету. «Особистий кабінет» додає групи квартири, історію, нагадування та передачу показів лише призначеному користувачеві у приватному чаті. Обидва режими підтримують локальні датчики живлення. [Особистий режим](docs/PERSONAL.uk.md).

**Кілька адрес, чатів або ботів? Достатньо одного встановлення.** Кожна адреса має власні сповіщення, датчики, вибір групи та профіль Telegram-бота. Залиште основного бота або додайте інший токен один раз на вкладці **Telegram-боти** та використовуйте профіль для кількох адрес. Дивіться [адреси, чати й боти](DOCS.uk.md#destinations).

У нових версіях Home Assistant додатки **add-ons** називаються **apps**. У старіших версіях меню має назву **Add-ons / Додатки**. HA Container не містить менеджера застосунків. Дивіться [вимоги Home Assistant](https://www.home-assistant.io/apps).

<a id="installation"></a>
## Встановлення

1. Встановіть [DTEK Monitor](https://github.com/groove-max/ha-dtek-monitor/blob/main/README.uk.md#installation). Додайте адресу для будинкових графіків або підключіть свій кабінет для особистого режиму.
2. Створіть бота через [@BotFather](https://t.me/BotFather), команда `/newbot`. Збережіть його токен.
3. Відкрийте **Налаштування → Застосунки → Встановити застосунок → ⋮ → Репозиторії**. У старіших версіях це **Додатки → Магазин додатків**.
4. Додайте `https://github.com/groove-max/ha-dtek-telegram-bot` і встановіть **DTEK Telegram Bot**. Оберіть поточну версію з магазину застосунків; [примітки останнього випуску](https://github.com/groove-max/ha-dtek-telegram-bot/releases/latest).
5. У **Конфігурації** введіть `telegram_bot_token`. Поле `telegram_chat_id` можна поки залишити порожнім — одержувача оберете в редакторі. Запустіть застосунок і натисніть **Відкрити вебінтерфейс**.
6. Відкрийте свого бота в Telegram і надішліть `/start`. Для групи додайте бота й надішліть `/start@ім’я_бота`; для каналу надайте права адміністратора на публікацію та редагування. Закріплення у групі/каналі потребує відповідних прав.
7. Пройдіть майстер нижче. На кроці **Telegram** натисніть **Оновити**, щоб вибрати себе або чат. [Якщо список порожній](DOCS.uk.md#telegram).

Зазвичай створювати токен доступу Home Assistant не потрібно: застосунок автоматично використовує доступ Supervisor.

<a id="setup"></a>
## Налаштування першого профілю

Для особистого використання достатньо розмови з ботом — створювати групу чи канал не потрібно. Для спільної розсилки спочатку перевірте налаштування в особистому чаті або тестовій групі.

1. У **Налаштуваннях** натисніть **Додати профіль**. Майстер пропонує **Графіки за адресою** або **Особистий кабінет**. Адресні графіки також можна отримувати приватно — спільний чат не обов’язковий.
2. Оберіть будинок або підключений рахунок і зрозумілу назву. Для всіх груп будинку залиште вибір групи порожнім. Особистий профіль використовує групи кабінету.
3. Оберіть бота й одержувача зі знайдених або введіть ID. Для кабінету потрібно явно вказати приватного власника; виявлення користувача не надає доступ автоматично.
4. Увімкніть потрібні сповіщення. Датчики живлення необов’язкові; напруга для статусу та попереджень налаштовується окремо.
5. Перевірте одержувача й сповіщення, натисніть **Застосувати**. Це перевірить, збереже налаштування та перезапустить застосунок. Після запуску почнеться надсилання повідомлень.
6. Перегляньте **Поточний стан**. Прев’ю шаблонів і тестове надсилання доступні в **Інструменти → Шаблони**. Тест надсилає справжнє позначене повідомлення в налаштований тестовий чат.

Кожен профіль має окрему картку; **Налаштувати** відкриває один редактор. Чернетки зберігаються при оновленні та переходах. Імпорт/експорт, перевірка й збереження без перезапуску доступні в **Додаткові дії**. Службові метрики та резервний токен HA не заважають першому налаштуванню.

**Ознаки успішного налаштування:** HA підключений, адресу й групу знайдено, тест з’явився в потрібному чаті, статусне повідомлення редагується. Без свіжих вимірювань локальний стан живлення цілком коректно може бути `unknown`.

Для примусового тестового спрямування в особистий чат, групу або канал перед запуском задайте `test_chat_id` у параметрах застосунку. Для будинкових профілів він замінює одержувачів. Особистий профіль і його тести шаблонів дозволяють лише приватний чат призначеного користувача. Докладніше: [ізольоване тестування](DOCS.uk.md#testing).

<a id="power-detection"></a>
## Як визначати наявність світла

| Що є у вас | Що обрати | Як визначається стан |
| --- | --- | --- |
| Немає локального датчика | Лише DTEK | Стан від оператора, без фізичного вимірювання. |
| Готовий бінарний статус у HA | Датчики Home Assistant → цей статус | Явна наявність/відсутність; оберіть, чи `on` або `off` означає наявність мережі. |
| Резервований датчик напруги або частоти | Датчики Home Assistant → вимірювання | Наявність/відсутність зі свіжого числового значення. |
| Два незалежні датчики напруги/частоти/статусу на одній лінії | Датчики Home Assistant + підтвердження | Узгоджені показання визначають стан; суперечність означає невідомий стан. |
| Датчик входу інвертора + лічильник, що вимикається | Датчики Home Assistant + «Вимикається разом із мережею» | Явний сигнал втрати від першого та замовкання раніше доступного другого можуть підтвердити відключення після очікування. |

Основний датчик, його зв’язок і HA мають працювати під час відключення. Вимірюйте **вхід міської мережі**, а не резервований вихід інвертора. Зникнення єдиного датчика, який живиться від мережі, не доводить відключення.

Напруга для статусу й попереджень обирається окремо. Наприклад, готовий бінарний статус керує сповіщеннями про світло, а інший датчик дає значення напруги. Два датчики однієї лінії не є двома фазами. Збережені `voltage_only` / `loss_plus_voltage` та їхня пофазова логіка підтримуються без автоматичного переналаштування.

[Налаштування датчиків, приклади, свіжість і правила переходів →](docs/POWER.uk.md)

Окремі сповіщення про втрату й повернення даних **типово вимкнені** (`power.telemetry_notifications: false`). Закріплений статус продовжує відображати відсутність вимірювань. Повідомлення про підтверджене відключення та відновлення залишаються доступними.

<a id="schedules"></a>
## Графіки, групи та статус

- Графік — це план, а не вимірювання. Аварійні обмеження ДТЕК можуть його змінювати.
- Кілька груп адреси відображаються окремо. Вибір групи не підтверджує, що саме до неї належить квартира.
- Для операторів із прихованими номерами показуються **«Варіант 1», «Варіант 2»**. Це локальні позначення, а не офіційні номери черг.
- Невдалі або неузгоджені перевірки призупиняють сповіщення про графік. Збережені календарі лише для перегляду не запускають сповіщень.
- Неопубліковану дату бот не оголошує днем без відключень.
- Типовий режим статусу редагує одне повідомлення. `send_new` доступний, якщо вам потрібні нові дописи.

<a id="troubleshooting"></a>
## Розв’язання проблем

| Симптом | Що зробити |
| --- | --- |
| Не знаходжу застосунок | Додайте репозиторій до магазину застосунків HA, не HACS. Перевірте спосіб встановлення HA та архітектуру процесора. |
| Немає адреси серед знайдених | Перевірте сутності будинку й з’єднання з HA. У Monitor 2.0 перевірте прив’язку будинку до рахунку; сам рахунок не є адресою для бота. [Інструкція підключення](DOCS.uk.md#dtek-monitor). |
| Monitor 1.7.0 показує «Current schedule coverage is missing» під час налаштування | Відома проблема інтеграції може блокувати створення сутностей. У Monitor 2.0.0b1 її виправлено; дивіться [оновлення та відкат](DOCS.uk.md#monitor-upgrade). |
| Список одержувачів порожній | Перевірте **Приймання команд**, надішліть новий `/start` після запуску й оновіть список. Виявляються лише нові події Telegram. [Інструкція](docs/PERSONAL.uk.md#виявлені-одержувачі-telegram). |
| Особисте меню чи історія недоступні | Перевірте [сумісні версії](docs/UPGRADING.uk.md), оберіть рахунок і приватного користувача, застосуйте та надішліть `/start`. Перевірте з’єднання кабінету в HA. |
| Немає повідомлень Telegram | Перевірте токен, повний ID чату й права бота; надішліть тест шаблону та перегляньте журнал застосунку. |
| Налаштування збережено, але поведінка стара | Скористайтеся **Застосувати** та перевірте індикатор незастосованих змін. |
| Стан живлення `unknown` | Перевірте доступність датчика, час звітування та максимальний вік даних. Старе число не підтверджує наявності світла. |
| Статус постійно надходить новими дописами | Перевірте `delivery_mode`: потрібен `pinned_edit` і можливість редагувати власне повідомлення. |
| Група повторюється у власному шаблоні | Скиньте цей шаблон до актуального стандартного або виправте перевизначення. Власні шаблони зберігаються після оновлення. |
| Сповіщення про графік зупинилися | Перевірте з’єднання DTEK Monitor та, у версії 2.0, **Доступність графіка**. Відсутня публікація не означає підтверджений порожній графік. [Стани доступності](DOCS.uk.md#schedule-availability). Контроль за локальними датчиками може продовжуватися. |
